# EP-05.02 — Application-specific form-question handoff

## Scope and requirement links

This task implements the unresolved-question handoff in `F-07.05`, `E-03`, `P-06`
and `S-24`, following the durable workflow and audit boundaries in `ADR-003` and
`ADR-008`. It extends EP-05.01 composition without adding a user interface,
notification transport, provider integration or external application action.

## Delivered behavior

- An unresolved form question can pause only a running `COMPOSE_ARTIFACT` task whose
  input is the exact application. The request binds the question and prompt hash,
  application, task, current opportunity version/content hash and request time.
- The application service records the immutable request before moving that exact task
  to `waiting_user`. Both calls require one caller-owned PostgreSQL transaction, so a
  failed transition rolls the request back rather than leaving a partial handoff.
- Resumption requires an approved answer bound to the same question and application,
  an exact content digest and a non-backdated `UserReview`. The answer record and exact
  task resumption share the same caller-owned transaction. Other tasks are untouched.
- PostgreSQL serializes answers per question with a transaction advisory lock. Exact
  repeated writes are idempotent, a conflicting second answer fails closed, and the
  application role cannot update or delete either audit table.
- Migration `0014_form_question_handoff` stores request and approved-answer evidence
  with foreign keys to the application, task and opportunity version. It grants only
  read/insert access to the application role and has no destructive downgrade.

## Verification

Verified locally on 2026-10-15:

- A transient offline orchestration probe confirmed the exact task moved from running
  to `waiting_user` and resumed to queued only with its approved answer.
- An internal-network PostgreSQL probe used the `acoa_app` role and synthetic records.
  It exercised request/answer idempotency, rejected a conflicting answer, confirmed
  update denial on both audit tables and resumed only the matching task. Its transaction
  was rolled back and the probe files were removed.
- The migration was applied to the dedicated development database and reported
  `0014_form_question_handoff (head)` without publishing a host port. The final gate
  passed 98 existing tests, Ruff lint/formatting, strict mypy across 84 source files,
  package consistency, migration graph/offline SQL checks, approved-document
  preservation and the 137-file active checksum manifest. No test, fixture, mock or
  testing utility was added or modified.

## Remaining boundaries

`UserReview` must come from a trusted authenticated human-input adapter; constructing
the Python value is not proof of user identity. Automatic lookup and reuse of prior
answers, notification delivery and a user-facing answer channel remain future work.
Artifact persistence/rendering remains EP-05.03/04. This workflow grants no permission
to share data and performs no employer or provider action.
