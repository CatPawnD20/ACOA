# EP-07.03 — Live dashboard reporting and masked audit view

## Scope and requirement links

This task completes the first dashboard package for `F-11.07`, `F-12.03`, `F-12.06`,
`F-12.07`, `E-08`, `E-11.03`, `P-09`, `P-17`, `P-22`, `ADR-009` and `ADR-010`.
It adds read projections and browser refresh behavior only; it does not deliver a
notification or create a daily report.

## Delivered behavior

- The dashboard polls its existing authenticated JSON endpoint every 15 seconds while
  the page is visible. It refreshes authority, metrics, application/task states,
  company counts, waiting work, costs, notifications, daily reports and audit activity.
  Structural row changes trigger a full same-origin reload so newly created or removed
  records cannot remain absent from the rendered view.
- Successful JSON refreshes rotate the actor-bound CSRF token returned in a response
  header, allowing a long-lived page to retain protected controls without extending any
  individual token lifetime. Failed refreshes remain visible in a small live-status
  label and do not erase the last known snapshot.
- The audit projection unions task, application, reconciliation, model-call and
  authenticated dashboard-control events. It selects explicit scalar columns only. It
  never reads JSON result/payload fields, evidence identifiers, actor digests, provider
  message identifiers, model inputs or stored content.
- Raw audit UUIDs are replaced with deterministic `ref-` labels derived from SHA-256 and
  truncated for local correlation. Important-notification application identifiers use
  the same masking. Browser updates construct DOM nodes with `textContent`; untrusted
  values are never inserted as HTML.
- Immediate mail-notification state and up to 30 closed daily mail reports are presented
  separately. Zero-result reports remain visible, preserving the approved distinction
  between urgent events and routine daily activity.

## Verification

Verified locally on 2026-10-16:

- A read-only, repeatable-read probe used the real internal PostgreSQL service and the
  `acoa_app` role. It loaded two audit events, one important notification and two daily
  reports, verified every exposed reference format and confirmed that forbidden JSON,
  actor, evidence and provider-message field names were absent from the serialized view.
- A disposable FastAPI container verified server-side HTML escaping, the authenticated
  JSON endpoint, CSRF-token rotation and the packaged polling script. A synthetic
  HTML-shaped audit category rendered as escaped text, and the updater contains no
  `innerHTML` use.
- The final gate covers 98 existing tests, Ruff lint/formatting, strict mypy, dependency
  consistency, wheel asset inspection, approved-document preservation and the 184-file
  active checksum manifest. No test, fixture, mock or testing utility was changed.

## Remaining boundaries

Notification delivery/read-state controls and user-selected quiet hours remain future
scheduler work because their values are still TBD. Retention enforcement, structured
operational logging and alerting belong to EP-10. The dashboard remains caller-configured
and has no remote listener or deployment in this task.
