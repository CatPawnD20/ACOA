# EP-08.02 — Risk-based browser-worker isolation

## Scope and requirement links

This task implements the browser process boundary for `F-08`, `E-04`, `E-07`,
`E-10`, `P-06`, `P-07`, `P-11`, `P-19`, `ADR-005`, `ADR-006`, `ADR-007` and
`ADR-012`. It does not visit an employer site, create an account, upload a real
document or submit a form.

## Delivered behavior

- `BrowserWorkerInvocation` binds one non-submit operation to the exact task and
  application permit, origin, capability set and expiry. The operation vocabulary
  contains inspect, draft fill and document upload only; no submission operation is
  exposed. External effects remain callable only from a trusted adapter selected by
  the central `ExternalActionExecutor` after its committed Policy/Budget Gate checks.
- `BrowserNetworkGuard` validates every initial navigation and redirect as bounded,
  canonical HTTPS on the permit's exact origin. It resolves the host for each hop,
  rejects duplicate, malformed and non-global answers (including loopback, private,
  link-local and cloud metadata addresses), enforces a redirect count, and returns the
  exact addresses the transport must use. URLs are hidden from object representations.
- The Playwright runtime is pinned in a dedicated image. The build context allowlists
  only the worker entry point and its two package markers; application code, Git data,
  local configuration, artifacts and secrets do not enter the image.
- The optional Compose worker starts as UID/GID 10001, with no network namespace route,
  no secrets or volumes, a read-only root, ephemeral no-exec temporary directories,
  all capabilities dropped, no-new-privileges, an init process and bounded CPU, memory,
  PID and shared-memory resources. It has no database network or credential.
- Safe deployment keeps `network_mode: none`. A later adapter may enable a narrowly
  controlled network only together with per-request interception that uses the guard's
  pinned endpoints. Docker isolation is defense in depth, not an absolute sandbox.

## Verification

Verified locally on 2026-10-16:

- A transient Python probe accepted an exact-origin public endpoint and rejected a
  cross-origin URL, the `169.254.169.254` metadata address, redirect overflow and an
  upload operation absent from the permit. No test, fixture, mock or testing utility
  was added or modified.
- Docker Compose rendered the browser profile with `network_mode: none`, no secret or
  volume mount, UID/GID 10001, read-only root, dropped capabilities, no-new-privileges
  and resource limits. The image build context was 3.04 kB after allowlisting.
- The one-shot container self-check passed non-root, no-default-route, read-only-root,
  no-secrets, exact Playwright 1.64.0 and a real headless Chromium launch/render check
  under the configured restrictions. The database service was not started or changed.
- The final repository gate covers the existing test suite, Ruff formatting/linting,
  strict mypy, dependency consistency, approved-document preservation and the active
  checksum manifest.

## Remaining boundaries

EP-08.03 owns authorized career-account creation and task-scoped credential references.
EP-08.04 owns the synthetic career site, the concrete intercepted Playwright adapter,
central-executor submission, timeout ambiguity and reconciliation. Public egress stays
disabled until that adapter can enforce every request and redirect; this task does not
claim that application-level URL checks alone provide kernel-level egress control.
