# EP-00.02 — Safe Configuration

Status: implemented and verified on 2026-10-14, under the user's authorization to continue.

## Objective and boundaries

Provide an immutable, validated configuration model, explicit TOML loading, a harmless example, and configuration-only readiness checks. Defaults are `dry_run=true` and `external_actions_enabled=false`. Missing, invalid, or zero mandatory limits cannot produce ready live-action configuration.

Trace: L4 EP-00.02; L2 section 9.5, E-02.01, E-07.01/E-07.03/E-07.06, P-04/P-10/P-17; ADR-006/011/015. This task checks configuration completeness; it does not implement those complete runtime policies.

## Subtask 1 — Model and pure validation

- **Goal/files:** add `src/acoa/config.py` with frozen settings and focused validators for flags, quotas, budget amounts/currency, an authorization-grant reference, authorized accounts, and allowed data categories.
- **Dependencies:** EP-00.01; standard library only.
- **Acceptance:** safe defaults, unset limits represented by `None`, strict field types, finite nonnegative amounts, and immutable account/data lists. Zero is valid configuration but blocks relevant operations. No arbitrary policy thresholds.
- **Checks/security:** exercise defaults, direct construction, invalid booleans/types/ranges/nonfinite values, and value-redacted errors. No account/provider access.

## Subtask 2 — Loading and readiness

- **Goal/files:** in `config.py`, separate explicit file reading, mapping conversion, and readiness decisions into named functions.
- **Dependency:** subtask 1.
- **Acceptance:** unknown fields and malformed/unreadable files fail closed; missing fields retain safe defaults; TOML monetary values retain decimal precision. Loading does not inspect environment variables or discover `.env` files.
- **Checks/security:** temporary synthetic TOML inputs cover successful loading and failure paths. Configuration completeness must not be labeled authorization. A grant ID must be resolved and checked against PostgreSQL-backed policy at execution time in later tasks.

## Subtask 3 — Example, verification, and delivery

- **Goal/files:** add `config.example.toml`, `tests/test_config.py`, update the existing import smoke check, `.gitignore`, pytest trace metadata, README/index, and the current checksum manifest. Record actual results here after verification.
- **Dependencies:** subtasks 1–2.
- **Acceptance:** example performs no I/O except when explicitly loaded, contains no real identifiers/secrets or configured spending limits, and remains blocked. All relevant smoke/negative tests and lint/format/type checks pass; approved document bytes remain unchanged.
- **Security:** ignore the real root `config.toml`; no `.env`, credentials, personal CVs, live provider, employer endpoint, database, or execution path. Tests use temporary files and synthetic identifiers. No dependency installation is needed.
- **Delivery:** review the scoped diff and create one local commit after runtime verification. No remote push, PR, deployment, or external action.

## Decisions

- TOML is loaded only from a supplied path using Python 3.12's `tomllib`. Missing files raise a redacted configuration error; no implicit production configuration fallback.
- The implemented parameter slice covers initial application/outreach limits, monetary/token/time caps, account/data scope declarations, and an existing authorization-grant reference. Later model/search/retention/notification/reapplication schemas remain with their owning tasks.
- Task time caps are expressed in seconds. Monetary caps use `Decimal`; a three-letter uppercase currency label is required for monetary configuration readiness. Provider-supported currency and conversions remain later budget-ledger concerns.
- Grant ID, authorized-account strings, and data-category strings are configuration declarations only. Completeness does not validate a grant's existence, expiry, revocation, action type, recipient, or legal/data-sharing scope.
- Numeric budgets/limits remain unspecified in the example. Zero closes the corresponding configuration gate; missing mandatory settings are never interpreted as unlimited.
