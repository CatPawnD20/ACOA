# EP-06.04 — Initial-mail acceptance, timeout and sent-record evidence

## Scope and requirement links

This task exercises the initial-application mail route for `F-08`, `F-09.01`, `E-04`,
`E-07`, `P-01`, `P-02`, `P-11`, `P-12`, `ADR-007` and `ADR-014`. It uses only a
synthetic test-mailbox adapter and opaque development identifiers. No Gmail account,
OAuth token, real recipient or live message was used.

## Delivered behavior

- The fake interaction adapter accepts only an exact policy-bound
  `submit_initial_application` draft and implements explicit accept, timeout after
  acceptance and timeout before acceptance outcomes. Each configured attempt can be
  invoked only once.
- A transport acknowledgement remains separate from read-only sent-record evidence.
  Timeout after provider acceptance returns no acknowledgement but reconciliation can
  later find the provider sent record. Timeout before acceptance yields an inconclusive
  lookup and remains `UNKNOWN`.
- Trusted evidence conversion binds the exact prepared action, provider, application,
  observation time and immutable sent-record snapshot. A sent record proves only
  `PROVIDER_ACCEPTED`; it never claims delivery or reading.
- PostgreSQL stores one immutable message/thread relationship per initial attempt and
  draft. The application role can read and insert these records but cannot update or
  delete them. Reply/follow-up sending remains absent.

## Verification

Verified locally on 2026-10-16 with synthetic content:

- A transient offline probe exercised all three provider outcomes. The accepted and
  timeout-after-accept cases reconciled to provider acceptance from sent records; the
  timeout-before-accept case remained unknown. All invocation counts stayed at one.
- Migration `0019_mail_sent_records` was applied to the internal-only PostgreSQL
  service. A transaction probe persisted an exact initial draft, dispatched attempt and
  message/thread record, verified idempotent replay and confirmed read/insert-only
  application privileges. The probes were removed afterward.
- The final gate covered 98 existing tests, Ruff lint/formatting, strict mypy, package
  consistency, migration graph/offline SQL, approved-document preservation and the
  active checksum manifest. No test, fixture, mock or testing utility was changed.

## Remaining boundaries

This is an offline provider conformance exercise, not live Gmail activation. The real
authenticated transport, sent-record lookup, protected snapshot retention and exact
cost reporting still require a separately controlled provider integration. Provider
acceptance does not establish delivery or reading, and an inconclusive lookup remains
unconfirmed without automatic resend.
