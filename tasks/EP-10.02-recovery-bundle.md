# EP-10.02 — Combined database and artifact recovery

## Scope and requirement links

This task implements the coordinated recovery boundary required by `E-05`, `E-11.05`,
`P-20`, `P-21`, `ADR-008`, `ADR-011` and `ADR-013`. It does not configure remote backup
storage, encryption keys, scheduling, production retention or a cloud target.

## Delivered behavior

- Compose declares a dedicated persistent artifact volume and an opt-in one-shot recovery
  service using the same digest-pinned PostgreSQL image. It has only the internal database
  network, migration password, recovery output and artifact mounts; capabilities are
  dropped and the root filesystem is read-only.
- Backup requires a quiet maintenance window. It verifies deployed artifact files against
  authoritative PostgreSQL metadata before producing a custom database dump, artifact tar,
  migration-head metadata and SHA-256 manifest in a create-only bundle directory.
- Restore accepts only a hash-valid versioned bundle, an empty isolated database schema and
  an empty artifact volume. It preserves correctly owned initializer schemas, restores data
  and ACLs, reapplies default application grants and checks the exact migration head.
- Final verification rejects links, unsupported objects, extra/missing artifact files,
  unsafe storage keys and any size or SHA-256 mismatch. Secret files are never archived.

## Verification

Verified locally on 2026-10-17:

- The recovery shell passed syntax and Compose rendering checks.
- A real custom-format backup of the development database and its empty artifact volume was
  created and checksum-verified under ignored `.tmp` storage.
- The bundle restored into new `acoa-restore-probe` PostgreSQL and artifact volumes. The
  restored migration head was `0025_generated_tool_records`; the application role retained
  artifact-table read access and the source deployment remained untouched.
- Deliberate artifact-archive corruption was rejected by SHA-256 verification and then
  reverted. The restored artifact count was zero, so nonempty byte matching relies on the
  earlier EP-05.04 synthetic logical recovery probe; no real personal artifact was used.
- The final repository gate covers the existing test suite, Ruff formatting/linting,
  strict mypy, dependency consistency, Compose rendering, approved-document preservation
  and the active checksum manifest. No test, fixture, mock or testing utility was added or
  modified.

## Remaining boundaries

The recovery bundle is not encrypted by this repository and must be stored in protected
external storage. No retention schedule or remote copy exists. A real local-to-VPS cutover
has not been performed. EP-10.03 owns service health and graceful shutdown, and EP-10.04–06
retain the configuration, pilot and explicit production-activation gates.
