# EP-04.04 — Conservative cross-source resolution and authorized fallback

## Scope and requirement links

This task implements cross-source organization/opportunity deduplication and source
fallback planning for `F-02.04/06`, `F-03.04`, `F-04.01`, `F-06.02/06/07`, `P-07`
and `ADR-005/006`. It consumes the source policies, access decisions, observations
and evidence-bound research records from EP-04.01–03. It performs no network access,
browser action, employer interaction or application submission.

## Delivered behavior

- Organization records become one canonical identity only when they already share an
  identity or current evidence explicitly verifies the same legal entity. A matching
  normalized name alone produces `possible_duplicate`; it never merges records.
- Opportunity records become one canonical identity only within the same canonical
  organization and when their stable identity or exact external job identifier
  matches. Matching role and location produce `possible_duplicate`; conflicting known
  locations remain distinct.
- Every decision binds the compared record IDs, outcome, basis, current evidence
  hashes, validity window and deterministic version identity. Evidence for an
  opportunity fingerprint must belong to that opportunity's source resource.
- A failed discovery observation can select only a different, unattempted source whose
  current policy permits every query data category and whose exact policy version has
  one current allow permit. Selection prefers official API, then search API, then
  public HTTP. Ambiguous current policies/permits fail closed; no eligible source
  produces an explicit terminal result.
- Migration `0013_cross_source_resolution` stores exact-repeat-idempotent decision and
  fallback records. Selected fallbacks retain the exact source policy version and
  permit identity. The application role has only `SELECT` and `INSERT`; retained rows
  cannot be updated or deleted.

  confirmed exact-repeat idempotency, conflicting-record rejection, direct-update

  published.
- Existing tests, lint, formatting, strict type checks, migration graph/offline SQL,

  are part of the final task gate. No test, fixture, mock or testing utility was added.

## Remaining boundaries

Real source adapters, learned similarity scoring and human resolution UI are not
implemented. Possible duplicates remain separate records for later review. A source
fallback plan authorizes no access by itself: execution must still recheck the current
source policy and permit. Real browsing, employer contact and application submission
remain disabled.
