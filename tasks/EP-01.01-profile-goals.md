# EP-01.01 — Verified Profile and User Goals

## Scope and acceptance

Implement framework-independent immutable domain values for sourced professional
claims, exact human review, profile variants, hard/soft goals, and stale-version
references. Trace: F-01.01–07; P-03/P-05/P-18; ADR-001/002. Continuous engineering
work is authorized; no real personal data or sending authority is inferred.

1. Represent fact kind/value, source references, status, version and timestamps.
   Sources alone never verify a claim. Only an exact user review can resolve it.
2. Bind review to ID, version and SHA-256 content. Reject stale decisions and
   changed content retaining an old approval. Corrections/conflicts remove approval
   in a new immutable version; prior snapshots remain intact.
3. Activate a variant only with its exact review and verified facts. Check activity
   and expiry at use time; never choose another variant silently.
4. Keep hard constraints distinct from soft preferences across role, industry,
   seniority, location, work model, compensation, language and employment type.
   Reject internally contradictory hard conditions. Preserve literal user values
   without inventing salary units or evaluating text as numeric criteria.
5. Track profile/goals version dependencies for later draft/assessment invalidation.
   Verify normal and failure behavior with direct synthetic runtime inputs and
   existing checks, without adding tests, mocks or fixtures.

## Trust and boundaries

`UserReview` is a domain record supplied only by a trusted human-input adapter.
It is not authenticated merely by its Python type or its hash. A content hash
prevents accidental review reuse after edits; it is not a signature or sending
permission. Later authenticated interfaces/persistence must prove the real user
decision, reject agent-supplied approval records, and retain review history.

Content versions change on corrections/conflicts; approving a fixed content version
changes its review/status metadata without changing the content version. Object
immutability preserves previous values; durable history and authoritative latest
versions belong to PostgreSQL persistence in later tasks. Domain constructors
validate reconstructed records but are not an access-control boundary against
arbitrary trusted Python code.

No CV parsing, real profile initialization, claim generation, goal ranking,
matching, database schema, dashboard, credential access or model call is included.
Conditions preserve user-declared labels/requirements. Compensation text is not
converted across currency/time units or treated as a computed numeric threshold.
Profile approval does not grant permission to share the profile externally.

## Verification

Verified locally on 2026-10-14 with Python 3.12.14 on Windows:

- Source-derived proposals stay unverified; exact human review resolves them.
  Duplicate review delivery is idempotent. Stale-version review and content edits
  retaining an approval are rejected, including direct reconstructed-record checks.
- Fact corrections/conflicts remove approval without modifying prior immutable
  values. Active variants require exact approval and verified facts; expiration is
  exclusive, and variant correction creates a new inactive version.
- Hard constraints and soft preferences remain separate; contradictory hard sets
  are rejected, and goals revisions invalidate exact dependent references.
- Personal fact/goal values do not appear in model representations or validation
  messages. Only synthetic inputs were used; no real CV/profile data was read.
- Existing **98 tests passed**; Ruff and strict mypy passed. No tests were added or
  modified. Focused direct probes exercise this new domain code separately from
  the existing package/configuration tests.

UTC-normalized digest timestamps prevent equivalent timezone representations from
invalidating an unchanged approval on persistence round trips. Guarded imports and additional source/variant rejection checks passed before commit.
PostgreSQL domain persistence, authenticated review ingestion and external sharing
were not exercised or implemented. These domain records do not prove a real user
authorization by themselves.
