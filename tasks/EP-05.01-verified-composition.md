# EP-05.01 — Verified profile composition

## Scope and requirement links

This task implements local deterministic CV, cover-letter and form-answer drafting for
`F-07.01–05`, `P-05`, `P-06`, `P-18` and the input-binding portion of `ADR-008`. It
consumes the approved profile and sourced opportunity records from EP-01.01 and
EP-04.02. It does not persist files, produce PDF/DOCX, submit an application or grant
permission to share personal data.

## Delivered behavior

- CV and cover-letter drafts require one exact application ID, a current active
  user-approved profile variant, a current sourced opportunity and an explicit list of
  verified profile facts. The deterministic renderer copies fact values without
  expanding dates, seniority, certifications or experience.
- Employer and role personalization uses only current `source_supported` opportunity
  fields. The resulting UTF-8 plain-text draft rejects invalid control characters and
  oversized content.
- Form questions bind their exact ID and prompt hash to one canonical profile-fact kind. A
  form answer is emitted only when the active profile contains exactly one matching
  verified fact; absent or ambiguous answers raise `UnresolvedFormQuestion` without
  inventing a value.
- Every draft binds its kind, application, profile variant ID/version/content hash,
  opportunity ID/version/content hash, selected fact ID/version/content hashes, optional
  question hash, exact content and composition time. Reuse checks fail when a profile,
  selected fact, opportunity or relevant source evidence becomes stale or changes.
  The raw UTF-8 content hash remains separate from the full source-binding hash.

## Verification

Verified locally on 2026-10-15:

- A transient runtime probe created only synthetic human-review and source-evidence
  records. It composed all three draft kinds, confirmed exact fact copying, rejected an
  unknown salary question, detected a changed opportunity version and confirmed no
  unapproved skill appeared. The probe was removed afterward.
- Existing tests, lint, formatting, strict type checks, package consistency, approved
  document preservation and the active checksum manifest are part of the final task
  gate. No test, fixture, mock or testing utility was added or modified.

## Remaining boundaries

Form-question-to-fact mapping must come from a trusted deterministic adapter; its Python
type alone is not proof of correct semantics. User-approved prior form answers and the
application-specific `waiting_user` transition belong to EP-05.02. Immutable artifact
versioning, PostgreSQL metadata, storage, PDF/DOCX rendering, retention and recovery
belong to EP-05.03/04. A local draft is not external-sharing authorization.
