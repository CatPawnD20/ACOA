# EP-06.01 — Provider-neutral mail and Gmail boundary

## Scope and requirement links

This task implements the provider-neutral mail contract and first Gmail API mapping for
`F-09`, `E-07`, `P-01`, `P-02` and `ADR-014`. It remains offline: no account, OAuth
client, token, mailbox or recipient was accessed and no message was sent.

## Delivered behavior

- Domain values validate canonical account/recipient addresses, bounded subject/body,
  exact UTF-8 body hashes, provider message/thread identities and immutable pages.
  Account, recipients, subject and body are excluded from dataclass representations.
- The provider contract exposes only mailbox-reference listing and draft creation. It
  has no send operation, so reply/follow-up or initial sending cannot bypass the later
  Policy Gate and External Action Executor.
- The fake provider is deterministic, offline and idempotent for one exact draft ID.
- The Gmail adapter maps to `GET /gmail/v1/users/me/messages` and
  `POST /gmail/v1/users/me/drafts` through an injected authenticated transport. It
  constructs RFC-style MIME locally and never accepts or logs an OAuth token itself.
- Gmail configuration accepts exactly `gmail.readonly` and `gmail.compose`; broader
  `mail.google.com`, `gmail.modify` and undeclared scopes are rejected. Google classifies
  both selected scopes as restricted, so account activation requires the applicable
  consent, verification and data-protection work before any live use.

## Verification

Verified locally on 2026-10-16 with synthetic addresses and content:

- A transient probe exercised fake inbox/draft behavior and Gmail request mapping,
  decoded the generated MIME payload, confirmed no send method exists, rejected missing
  and extra OAuth scopes and confirmed private draft text is absent from `repr`. The
  probe was removed afterward.
- The final gate passed 98 existing tests, Ruff lint/formatting, strict mypy, package
  consistency, approved-document preservation, local links and the active checksum
  manifest. No test, fixture, mock or testing utility was added or modified.

## Remaining boundaries

The declared scope object does not authenticate a user or prove the scopes on an actual
token; a trusted OAuth/HTTP transport and controlled test-account handshake are still
required. Inbox cursors and event deduplication are delivered by EP-06.02; draft policy
and persistence belong to EP-06.03, and send/reconciliation tests to EP-06.04. Until
EP-06.03 persists remote
draft outcomes, callers must not blindly retry an uncertain draft-creation result. Real
OAuth setup is a separate security-sensitive activation and remains disabled.
