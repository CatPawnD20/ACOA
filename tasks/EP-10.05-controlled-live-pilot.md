# EP-10.05 — Controlled Gmail live-pilot boundary

## Scope and requirement links

This task prepares the G4/S4 live Gmail handshake for `F-08`, `E-04`, `E-07`, `E-08`,
`E-11`, `P-01`, `P-02`, `P-04`, `P-10`, `P-11`, `P-17`, `ADR-007`, `ADR-009`,
`ADR-011` and `ADR-013`. It does not activate production or authorize a real employer
target.

## Delivered behavior

- A controlled mail target binds the exact sender, recipient, opaque account/recipient
  identities, control evidence, finite validity window and affirmative human review.
- The Gmail interaction adapter accepts only one exact policy-bound initial-application
  draft for that target. Reply, follow-up, multi-recipient and stale/mismatched requests
  are rejected before provider I/O.
- The controlled pilot is self-send only. Immediately before submission, a read-only Gmail
  profile lookup must match the reviewed sender identity; a mismatch blocks the send call.
- The provider call uses the existing committed `prepare -> reserve -> execute once`
  boundary. A deterministic RFC Message-ID binds the external message to the attempt.
- Read-only reconciliation searches Gmail Sent by that exact Message-ID and produces an
  immutable `MailSentRecord`; an empty result stays inconclusive and never triggers a
  retry.
- An explicit pre-execution cancellation transition releases a reservation and stores
  immutable cancellation evidence. Executing or later attempts cannot be cancelled.
- OAuth bootstrap uses Google's desktop loopback flow, exact readonly/compose scopes,
  create-only ignored token storage and redacted transport errors. Integration packages
  are pinned separately from the base application.

## Live gate

The code and offline failure/retry/cancellation checks were completed without committed
personal data. The first authorized live handshake exposed a private configuration mismatch:
the reviewed sender did not identify the OAuth account, while Gmail enforced the authenticated
identity. No retry was performed. A later read-only reconciliation verified the exact Sent
record through its attempt header, content, authenticated sender, recipient and provider
timestamp; the identity mismatch remains recorded in private evidence. The private target was
corrected without adding an address or token to Git, and the adapter now fails closed on this
mismatch before its send request. A second explicitly authorized self-send passed the corrected
identity boundary and reconciled as provider-accepted. Further live sends still require current
private readiness and explicit authorization.

Production activation remains EP-10.06. Provider acceptance from this pilot will not be
reported as delivery or reading.
