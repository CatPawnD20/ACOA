# EP-03.02 — Bounded offline routing and quality gates

Trace: E-01/E-02/E-06; P-03/P-10/P-17; ADR-004/015.

## Scope and behavior

Human decisions take precedence; sufficient deterministic T0 work invokes no model.
Otherwise explicit risk, uncertainty and complexity establish the minimum T1/T2/T3
tier. Selection requires current provider/data permission, a dated quality estimate,
an explicit quality target and token, time, money and escalation limits. Missing
configuration defers work. Candidates are ordered by tier, quoted cost and latency.
There is no production model catalog, invented price or default quality threshold.

The workflow records a versioned route, invokes the existing offline gateway and
accepts output only after a trusted evaluator reports sufficient quality and all
structure, grounding, task-relevance and instruction-isolation checks pass. Reports
bind both request and output hashes; a high score alone is insufficient. The audit
store independently checks the persisted target and routing policy. Known quality
failure permits only the bounded planned fallback; unknown delivery, a blocked
gateway, unknown quality or a human decision cannot trigger another provider call.

Current PostgreSQL provider scopes are checked again immediately before dispatch,
under the same authority lock as budgets. Revocation, expiry, changed policy and
unknown data classification block a call. Permission updates use revision checks
and immutable history; revoked policy versions cannot be re-enabled or reinstated.
Migration `0007_model_routing` adds these records and immutable route/quality audit.
Application privileges deny modification/deletion of audit history. Only hashes,
versions, classifications and bounded operational metadata are persisted, not raw
prompts or output bodies.

Late valid receipts after deadline recovery settle actual usage honestly but fail
the call and pause authority. They cannot return an accepted output or cause a
second provider invocation. Unknown receipts continue to retain resource holds.

## Observed local verification

- Existing baseline: 98 passed. No test, fixture, mock or test utility files added
  or modified. Focused runtime probes used transient inline synthetic adapters.
- Pure routing: T0 and human precedence, T1/T2/T3 severity selection, unauthorized
  free-provider exclusion, missing targets/limits, token/money bounds and forbidden
  personal-data scope. Structured routing decisions carry policy and quality target.
- PostgreSQL: absent/revoked/unknown scopes, stale routing policy, same-version
  re-enable and historical-version replay rejected. A deliberately mismatched
  stored provider identity was rejected inside a rolled-back probe transaction.
- Offline workflow: T0 made zero provider calls; low-quality T1 escalated to T2;
  zero escalation stopped after one stage; human requirements stopped escalation;
  revocation between stages prevented the next provider callback.
- Quality audit: below-target forged approval and wrong request hashes rejected.
  Unknown scores, wrong output hashes, failed required checks and human requirements
  could not be bypassed by a high numeric score. Evaluator exceptions require review.
- Expired-call recovery followed by a late valid receipt recorded known cost, failed
  the call and paused authority. Scoped synthetic records were cleaned; synthetic
  permission history retained, current providers disabled and safe authority restored.
- Ruff lint/format, strict mypy (44 application/test files, 10 deployment files),
  isolated imports with network/process/thread/private-configuration guards passed.
- Maintenance image rebuilt; repeated upgrade succeeded at `0007_model_routing`.
  Dedicated PostgreSQL retained its volume and returned to unpublished host ports.

## Remaining boundaries

All provider and evaluator behavior exercised here was synthetic. No live model,
real quality benchmark, user data, network adapter or production pricing was used.
Numeric quality estimates, severity assessment and classifications must come from
trusted future adapters; a UUID/hash is not authentication. Python callbacks do not
provide OS isolation or enforce cancellation of arbitrary code. Raw-output cache,
minimal-context construction and untrusted-source separation belong to EP-03.03.
Authenticated permission ingestion and real adapter limits remain activation gates.
Dry-run and disabled external actions remain the defaults; routing is never employer
action authorization. Hosted CI has not run because no remote repository exists.
