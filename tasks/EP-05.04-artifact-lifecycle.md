# EP-05.04 — Artifact privacy, retention and recovery

## Scope and requirement links

This task implements the artifact lifecycle slice of `F-07`, `E-05`, `P-17`, `P-20`
and `ADR-008`. It adds deterministic privacy classification, fail-safe retention,
local immutable storage and hash-verified logical backup/restore. It uses synthetic
content only and does not authorize sharing or configure production backup media.

## Delivered behavior

- Every persisted application artifact is classified conservatively as professional
  profile plus contact details and its material category. Sensitive document categories
  are rejected by this workflow and remain subject to separate explicit consent.
- Application artifacts use `application_history` retention. No default TTL or deletion
  path exists, so temporary-cache cleanup cannot erase application history.
- The filesystem adapter is rooted at one explicit directory, rejects traversal and
  symlinked parents, creates files exclusively, verifies exact existing content and
  never overwrites an immutable storage key.
- Logical backups pair exact artifact metadata with bytes and bind their ordered record
  hashes and creation time. Creation and restore verify storage key, media type, byte
  size and SHA-256. Missing, corrupt or mismatched content fails closed.

## Verification

Verified locally on 2026-10-16:

- A transient probe persisted synthetic CV bytes, confirmed nonsensitive history
  classification, created and restored a backup into a separate root, then detected
  deliberate byte corruption and rejected a root-escape key. Temporary files were
  removed afterward.
- The final gate passed 98 existing tests, Ruff lint/formatting, strict mypy, package
  consistency, approved-document preservation, local-link checks and the active-file
  checksum manifest. No test, fixture, mock or testing utility was added or modified.

## Remaining boundaries

This is an artifact-level logical recovery check. A crash-consistent PostgreSQL plus
artifact-volume recovery point, encryption/key management, remote backup destination,
scheduled retention execution and operational recovery exercise remain EP-10.02 work.
PDF/DOCX rendering is not implemented. Storage presence still grants no external-use
or data-sharing authority.
