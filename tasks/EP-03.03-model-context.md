# EP-03.03 — Minimal model context, untrusted-data separation and cache identities

Trace: E-02.03/E-02.04, E-05.06/E-05.07, E-07.03/E-07.04; P-10;
ADR-004/015.

## Scope and behavior

Model context is now assembled from an explicit selection rather than a caller's
whole profile or history. Profile fields are read only from a current active profile
variant whose facts have already passed exact user review. The caller names each
needed fact and its trusted data classification. External source records bind content
to source/version, observation time, expiry and digest. Unknown classifications,
missing approved facts, stale sources, duplicate source identities and oversized
context fail closed; evidence is never silently truncated.

The packed schema keeps `verified_profile_data` and `untrusted_external_data` in
separate closed fields. External content is preserved as data even when it contains
text such as “ignore previous instructions”; pattern matching is not treated as a
security control. The provider input carries a fixed boundary instruction, a separate
application task instruction and the context JSON. It contains no task, lease, route,
provider or authority identifiers. Model providers still have no tools, permissions
or direct external-action path, and instruction-isolation remains a mandatory quality
check before output can pass.

The full private prompt/context participates in the in-memory request digest, while
only that digest and an allowlisted classification trace are persisted. `repr` hides
task instructions, context, execution fences and provider bodies. The PostgreSQL
gateway rechecks the current provider/data permission before the projected payload
reaches an adapter.

Cache support in this episode is intentionally limited to identity derivation. A
cache key is HMAC-SHA-256 over prompt/context hashes, provider/model, schema, routing
policy, required quality, topic, risk and explicit TTL policy. It excludes volatile
task/lease/call identifiers, so equivalent public work can share an identity without
putting raw content in the key. Source expiry shortens the TTL. Personal or sensitive
context, unknown classification, stale context and weak/missing key material are not
cacheable. No output body or cache table is introduced before protected storage and
lifecycle deletion are designed.

## Observed local verification

- Existing baseline: 98 passed. No test, fixture, mock or test utility file was added
  or modified; focused probes used transient inline values and adapters.
- An injection-shaped external string remained only in the untrusted-data field;
  it did not appear in task instructions, object representations or persisted trace.
- The provider projection exposed only model/prompt/schema labels, fixed boundary,
  task instruction and context. Task, lease, route, provider and authority IDs were
  absent. The gateway created the internal output binding itself.
- An approved profile field could be selected; absent/unapproved profile state,
  unknown sensitivity, stale evidence and context byte overflow failed closed.
- Public cache identities were stable when only call/task/lease/route IDs changed,
  and changed with prompt version, context, quality or policy inputs. Personal
  context and key material shorter than 32 bytes were rejected.
- A real local PostgreSQL transaction exercised current provider permission, task
  lease, budget reservation, projected fake-provider call and trace inspection. The
  prompt/context were absent from stored metadata; every synthetic row was rolled
  back. The database returned to unpublished host ports.
- Ruff lint/format and strict mypy (47 application/test files) passed. Hosted CI was
  not run because no remote repository exists.

## Remaining boundaries

The classifier, profile/source loader and future provider adapter are trusted
composition boundaries; UUIDs and hashes do not authenticate them. Structural role
separation reduces accidental disclosure and instruction confusion but does not prove
a model will resist every adversarial text. Outputs remain untrusted and cannot grant
authority. There is no live model SDK, encrypted cache payload, cache lookup/store,
automatic lifecycle cleanup or real user data in this episode. Production TTLs,
quality targets and model pricing remain unset rather than invented.
