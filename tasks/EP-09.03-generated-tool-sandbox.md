# EP-09.03 — Isolated short-lived generated-tool sandbox

## Scope and requirement links

This task implements the generated Python helper isolation required by `E-07`,
`E-09.01`, `E-09.03`, `E-10.04`, `P-14`, `S-32` and `ADR-012`. It grants no browser,
database, secret, package-installation or external-action capability.

## Delivered behavior

- A dedicated dependency-free image contains only the sandbox worker and package marker.
  Git data, application modules, local configuration and secrets remain outside its
  allowlisted build context.
- Compose runs the optional worker as UID/GID 10002 with no network namespace route,
  database network, secret or persistent mount; root is read-only, temporary storage is
  no-exec tmpfs, all capabilities are dropped, new privileges are blocked and CPU,
  memory and PID counts are bounded.
- The worker accepts one bounded versioned JSON request. Source, input, timeout and output
  sizes have hard ceilings. Generated code may define one `transform(payload)` function;
  imports, top-level execution, dunder access and dangerous builtins are rejected.
- The generated function executes in a separate isolated Python child with a small safe
  builtin set, scrubbed environment, CPU/file/open-file/process limits and a wall timeout.
  It can return only a bounded JSON object. Source and private input are not logged.
- The worker has no method for package installation, application-code mutation, browser
  work, DB access, provider calls or External Action Executor invocation. EP-09.04 owns
  validation and mediation of any proposed output.

## Verification

Verified locally on 2026-10-16:

- The container self-check passed non-root, no-default-route, read-only-root, no-secrets
  and explicit sandbox marker checks under the Compose restrictions.
- A real isolated child transformed synthetic `[2,3,5]` input into the expected count
  and total JSON object.
- A generated script containing `import os` was rejected before execution. An infinite
  loop was terminated by the configured child/container resource bounds.
- The final repository gate covers the existing test suite, Ruff formatting/linting,
  strict mypy, dependency consistency, Compose rendering, approved-document preservation
  and the active checksum manifest. No test, fixture, mock or testing utility was added
  or modified.

## Remaining boundaries

The sandbox output is untrusted data. EP-09.04 must bind it to an exact request and
validate it before ordinary application code may consume a proposal. It can never gain
direct submission rights or bypass Policy/Budget Gate and External Action Executor.
