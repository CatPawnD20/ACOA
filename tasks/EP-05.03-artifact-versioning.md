# EP-05.03 — Immutable artifact versioning and storage binding

## Scope and requirement links

This task implements immutable application-artifact versions for `F-07.03–04`,
`E-05`, `E-06` and `ADR-008`. It records exact draft provenance and portable storage
identity without selecting a storage vendor, rendering PDF/DOCX, applying retention
or authorizing external use.

## Delivered behavior

- Each artifact version binds one application, material kind, source draft and source
  binding hash, exact byte hash/size, media type, deterministic storage key and time.
- The storage contract is provider-neutral. The application workflow writes immutable
  bytes, reads them back and registers metadata only after exact verification. A failed
  read-back leaves no database reference to unverified bytes.
- PostgreSQL serializes versions per artifact identity. Version one must start a series;
  later versions must be consecutive and retain the application and material kind.
  Exact repeats are idempotent and conflicting records fail closed.
- Migration `0015_artifact_versions` stores metadata only. The application role can
  read/insert but cannot update/delete artifact history.

## Verification

Verified locally on 2026-10-15 using synthetic content only:

- A transient offline probe persisted distinct CV artifacts for two applications and
  prevented metadata registration after a corrupt storage read-back.
- An internal PostgreSQL probe used `acoa_app`, recorded two consecutive versions,
  confirmed exact-write idempotency, rejected a skipped version and confirmed update
  denial. The transaction was rolled back and probe files were removed.
- Migration `0015_artifact_versions` is the single applied head. The final gate passed
  98 existing tests, Ruff lint/formatting, strict mypy, package consistency, migration
  graph/offline SQL, approved-document preservation and the active checksum manifest.
  No test, fixture, mock or testing utility was added or modified.

## Remaining boundaries

The interface does not claim that a storage backend is durable or private; production
backend configuration, retention, corruption recovery and backup/restore belong to
EP-05.04. Manual-edit approval semantics and rendered file validation also remain
future work. Artifact existence is not authorization to share or submit it.
