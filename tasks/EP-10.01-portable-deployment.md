# EP-10.01 — Portable image set and single-active cutover

## Scope and requirement links

This task implements the image-identity and cutover boundary required by `E-10`,
`E-11.05`, `E-11.06`, `P-21`, `ADR-011`, `ADR-012` and `ADR-013`. It does not perform a
cloud deployment, copy secrets, restore retained data or add a nonexistent API/worker.

## Delivered behavior

- The base Compose file names every runtime image without a build definition. A separate
  local build overlay creates the migration, browser and sandbox images from their existing
  allowlisted contexts. The same base definition can consume those selected images on a
  compatible local or VPS Docker host.
- The committed `acoa-portable-images/1` lock binds PostgreSQL and all three project images
  to exact content IDs and Linux platforms. Mutable tags remain locators rather than proof.
- A standard-library verifier checks all 227 active-file hashes, derives a source-set
  SHA-256 without a manifest/lock cycle, inspects Docker images without a shell and fails
  on missing images, changed IDs, changed platforms or source drift.
- The deployment guide defines a fail-closed handoff: verify identity, enter safe mode,
  stop and inspect the source, use the later verified recovery procedure, validate the
  isolated target, then start exactly one authoritative environment.
- Failure handling keeps the target stopped. Source restart is permitted only after
  confirming the target did no work and deliberately selecting source data as authoritative.

## Verification

Verified locally on 2026-10-17:

- Base, local-access and build-overlay Compose configurations rendered successfully.
- The locked `linux/amd64` PostgreSQL, migration, browser and sandbox image IDs matched
  Docker inspection, and the verifier emitted stable source-set/image-set SHA-256 values.
- A changed lock identity and changed active source file each caused verification to fail
  before any service action.
- The existing test suite, Ruff formatting/linting, strict mypy, dependency consistency,
  migration graph/offline SQL, approved-document preservation and active checksum manifest
  are included in the final gate. No test, fixture, mock or testing utility was added or
  modified.

## Remaining boundaries

No VPS was provisioned and no image archive, secret or retained database/artifact data was
transferred. EP-10.02 must implement and prove a consistent PostgreSQL plus artifact-volume
recovery point before a real cutover. EP-10.03 owns main service health, safe shutdown and
failure-mode operation. Real external actions remain disabled.
