# EP-10.04 follow-up — Codex-only execution limits

## Scope and requirement links

This follow-up records the user-approved execution policy under `E-02.01`, `P-10`,
`ADR-006` and `ADR-011`. It extends configuration and activation readiness without
enabling external actions, adding a paid model provider or changing authorization scope.

## Approved limits

- Application discovery/initial-application capacity: 100 per day and 700 per week.
- First outreach capacity: one per company and one per contact.
- Paid external model services: disabled, with explicit daily and monthly caps of USD 0.
- Per-task token ceiling: 30,000.
- Absolute per-task time ceiling: 7,200 seconds.
- No-progress timeout: 1,200 seconds.
- When Codex usage is unavailable, queued work is preserved and paused until access is
  available again.

## Delivered behavior

- Budget configuration distinguishes paid-service operation from Codex-only operation.
  Paid-service mode still requires positive money caps. Codex-only mode requires both
  money caps to be explicitly zero, so a positive paid estimate remains blocked.
- Configuration and activation readiness reject zero or missing execution ceilings and
  reject a progress-stall timeout above the absolute task ceiling.
- Dashboard reads and writes preserve the paid-service flag and progress-stall timeout.
- Existing persisted authority records remain compatible: records without the new flag
  retain paid-service semantics and therefore cannot silently reinterpret zero spend as
  ready.

## Runtime boundary

The repository has no continuously running Codex scheduler or worker. The approved
no-progress and usage-renewal behavior is therefore represented as validated policy for
that future runner; this change does not claim real-time enforcement. Dry-run and external
action defaults remain unchanged.

## Verification

Local verification covers the approved Codex-only values, contradictory paid-service
and monetary-cap combinations, the stall/absolute-time relationship, dashboard value
preservation, existing tests, Ruff, strict mypy, and the active checksum manifest. No
test, fixture, mock or testing utility was added or modified.
