# EP-08.04 — Synthetic browser submission and timeout reconciliation

## Scope and requirement links

This task implements the controlled browser-submission acceptance gate for `F-08.01`,
`F-08.03`, `F-08.04`, `F-08.07`, `E-04.02`, `E-07.03`, `P-06`, `P-07`, `P-11`,
`P-19`, `ADR-005`, `ADR-006`, `ADR-007` and `ADR-012`. It uses only reserved
`.invalid` identity data and an in-process synthetic career site.

## Delivered behavior

- `BrowserSubmissionAdapter` accepts only an exact prepared
  `SUBMIT_INITIAL_APPLICATION` request on the web channel. It delegates one bounded
  provider call and returns a transport acknowledgement to the existing central
  `ExternalActionExecutor`; it does not add a second execution or retry path.
- The synthetic provider uses a real headless Chromium session to load a controlled
  HTML form, fill the name and email, upload a fake PDF resume and click submit. Every
  request is intercepted in process, the origin is fixed to `career.test.invalid`, and
  the worker remains in its no-network container.
- The provider verifies the digest of every form value and the resume bytes against
  the prepared request. It rejects real email domains, non-PDF material, foreign
  providers, unsupported action kinds and attempts not configured for the test site.
- Error injection distinguishes normal acceptance, timeout after acceptance and timeout
  before acceptance. The provider counts calls and rejects a second submit for the same
  attempt. Transport timeouts therefore remain unconfirmed until reconciliation.
- A separate read-only status contract converts an exact attempt observation into
  evidence. A stored receipt proves provider acceptance; an authoritative empty record
  after the one invocation proves not performed; a lookup before invocation remains
  unknown. The recheck never opens the form or invokes submit.

## Verification

Verified locally on 2026-10-16:

- The browser probe ran as UID/GID 10001 in the existing read-only Playwright worker,
  with no network, no capabilities, no new privileges and bounded process, CPU, memory
  and shared-memory resources.
- Real Chromium completed the normal form and fake PDF upload. Both injected timeout
  paths returned no transport receipt. Read-only recheck classified the timeout after
  acceptance as `provider_accepted` and the timeout before acceptance as
  `confirmed_not_performed`.
- All three scenarios recorded exactly one provider invocation. No retry, external
  network request, real identity, credential, document or employer system was used.
- The final repository gate covers the existing test suite, Ruff formatting/linting,
  strict mypy, dependency consistency, approved-document preservation and the active
  checksum manifest. No test, fixture, mock or testing utility was added or modified.

## Remaining boundaries

The Playwright career site is deliberately a fake acceptance adapter and cannot target
a real host. Public browser egress, a production site adapter and live application
submission remain unconfigured. EP-08.05 owns the optional AI-guided browser path and
must preserve the same central executor, evidence and no-retry boundaries.
