# EP-07.02 — Authenticated dashboard controls

## Scope and requirement links

This task implements the dashboard control slice for `F-11.04`, `F-12.03`, `F-12.04`,
`E-03`, `E-07`, `E-08`, `P-01`, `P-17`, `P-22`, `ADR-006`, `ADR-007`, `ADR-010` and
`ADR-013`. It adds no listener, remote deployment, provider integration or external
action activation.

## Delivered behavior

- An explicitly secured dashboard verifies one caller-injected owner credential on the
  server using a constant-time PBKDF2-SHA256 verifier. The plaintext password, signing
  key and credential source are not stored, discovered or logged by the app factory.
- Every mutating endpoint additionally requires a short-lived HMAC CSRF token bound to
  the authenticated actor. Responses disable caching and set restrictive content,
  framing and referrer headers. Static assets contain the limited JavaScript needed to
  submit JSON controls.
- Entering safe mode atomically pauses authority, restores dry-run and disables external
  actions. Resuming orchestration preserves those fail-safe execution settings. Queue
  claims stop while authority is paused, so scheduled work cannot start in the pause
  window.
- Quota and budget fields can be replaced through validated typed values. Authorization
  scopes, accounts, privacy settings and live-execution flags are preserved. Currency
  changes remain subject to the existing ledger reconciliation guard.
- Queued or retry-scheduled tasks can move to a new non-active `paused` state and return
  to the queue. Active leases are rejected instead of racing a worker. Cancellation keeps
  the existing worker fence and explicitly does not claim to undo an action that already
  started. Waiting-user tasks still require their exact answer-evidence workflow.
- Each successful control has an idempotent request identifier, a pseudonymous actor
  digest and an immutable database audit event. Authority changes use that event as
  change evidence in the same transaction. Reusing an identifier for another actor,
  action or task is rejected.

- A disposable container rendered the protected dashboard and exercised the actual HTTP

  authenticated control returned 200 without exposing the supplied credential.
- The final gate covers the 98 existing tests, Ruff lint/formatting, strict mypy,
  dependency consistency, migration graph/offline SQL, wheel asset inspection, approved
  document preservation and the active checksum manifest. No test, fixture, mock or
  testing utility was added or modified.

## Remaining boundaries

The application factory still requires a deployment-owned credential source, database
engine and network binding. Remote use requires HTTPS or a trusted VPN in addition to
the implemented authentication and CSRF controls. Live external-action activation
remains a separate manual EP-10.06 gate. EP-07.03 owns polling, audit masking and daily
report presentation.
