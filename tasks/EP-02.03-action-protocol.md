# EP-02.03 — Atomic authority, reservations and one-attempt dispatch

## Scope and acceptance

Trace: F-08/F-10; E-04/E-05/E-07; P-01/P-02/P-10/P-11/P-17;
ADR-002/006/007/013. Implement side-effect-free preparation, persisted current
authority, atomic quota/money reservation, current-state dispatch recheck and one
automatic provider invocation. Transport acknowledgement starts reconciliation;
it never becomes verified submission by itself. Evidence-backed terminal
reconciliation, incidents and abandoned-attempt recovery continue in EP-02.04/05.
There is no real provider implementation, secret discovery, employer connection,
user ingestion endpoint or automatic sending activation in this task.

## Transaction and trust boundaries

`PreparedAction` binds an application/semantic key, exact request, plan, artifact
ID/version/content hash and registered provider. Validation evidence additionally
binds the entire preparation hash, preventing reuse with another application,
plan, artifact version or provider. Preparation checks the open unsent canonical
episode and is idempotent even after dispatch; this cannot cause another send.

`AuthorityStore` accepts only trusted authenticated human/config-adapter output.
Typed grants, reviews and change-evidence UUIDs do not authenticate a user.
No such public adapter is supplied here. Settings, pause, current grant/consents,
and the explicitly configured accounting timezone are authoritative PostgreSQL
state. Update uses a revision compare-and-swap under the same singleton row lock
as reserve/dispatch. Immutable history prevents reinstating old revoked versions
or changing existing version contents/approval receipts. A version can gain its
first exact approval. Invalid/missing authority fails closed. Default authority
is dry-run, external actions disabled, no grant, no timezone or invented limits.

Trusted validation adapters publish bounded-lifetime material/account/company/
hard-rule/opt-out evidence and provider estimates. They cannot supply usage or
current authority: these inputs are discarded and recomputed from PostgreSQL.
Evidence cannot change request/preparation identity or move backward in time.
Actual provider integrations must resolve/invalidate current source, profile,
opt-out and account facts; this task does not authenticate those upstream facts.
Agents and generated tools must not receive authority-store or executor access.

The global authority row serializes reserve, dispatch and authority/evidence
updates. The lock order then follows canonical series/application, attempt and
evidence rows. A partial unique index fences the semantic operation. Each episode
gets at most one automatic dispatched attempt, including after a known failure;
any future manual retry policy needs separate explicit implementation/authority.
A cancelled pre-dispatch hold can be replaced, since no provider was called.

Quota totals and money holds come from durable records, excluding this attempt's
own reservation during its dispatch recheck. Pending/unknown reservations remain
charged across period boundaries until reconciled. Failed dispatched attempts are
conservatively counted against contact/application caps. Money uses exact Decimal
and one declared currency; no exchange-rate conversion or automatic quota reset
on a new grant is introduced. Currency changes with ledger history require separate
reconciliation. An updated quote is rechecked before refreshing the same hold.

Dispatch commits a unique token and marks application delivery unconfirmed before
provider I/O. This is the dispatch linearization point: revocation/pause committed
before it prevents dispatch; an already dispatched in-flight effect cannot be
undone by a later pause. A crash before the actual call is conservatively ambiguous.
Concurrent/repeated calls cannot obtain a second token. Provider calls occur
outside the database transaction and have no automatic retry. Exceptions, missing,
foreign or malformed acknowledgements remain unconfirmed; a valid acknowledgement
only enters `reconciling`. If response persistence fails, the durable executing
record remains for reconciliation instead of another submission.

The adapter receives a deadline bounded by grant/evidence/task and applicable
sensitive-consent expiry, an I/O timeout and the exact reserved maximum cost.
Executor refuses an already expired ticket. Real adapters must enforce these
limits again at final submit and disable SDK retries; arbitrary trusted Python
callbacks cannot be forcibly interrupted by this synchronous interface. Actual
provider timeout/cost enforcement and OS process isolation remain integration
verification gates. No real adapter is registered by repository code.

Structured immutable decision rows retain policy/reason codes, authority revision,
request/context/preparation hashes and dispatch bounds without raw profile/account
data. Authority/evidence payloads are private database records, not public exports.
Application engines must have SQL echo disabled and `hide_parameters=True`.
Dependencies are the existing explicit PostgreSQL/migration tool requirements;
the pure application executor depends on a protocol, not SQLAlchemy or driver I/O.
