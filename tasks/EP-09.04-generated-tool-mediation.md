# EP-09.04 — Generated-tool output mediation

## Scope and requirement links

This task implements the narrow generated-tool output boundary required by `E-03`,
`E-07`, `E-09`, `E-12`, `P-13`, `P-14`, `S-32`, `ADR-012` and `ADR-015`. It does not
grant generated code a browser, provider, database or external-action capability.

## Delivered behavior

- Requests bind one task and replay-only experiment to exact source/input hashes, a
  sandbox timeout, an output-size ceiling and an explicit expiry.
- Executions retain exact request, source, input, output and worker-image hashes plus a
  terminal state. Only a successful execution observed within the bound request lifetime
  can enter mediation.
- The mediator accepts only the versioned `acoa-generated-tool-proposals/1` JSON schema.
  It rejects unknown fields, malformed or oversized output, duplicate targets and any
  operation outside source queries, research priorities and strategy notes.
- Valid results become inert planning proposals with deterministic identities. The
  mediation module exposes no External Action Executor, browser, mail or submission port.
- Migration `0025_generated_tool_records` stores append-only request, execution and
  proposal audit records. Exact-content idempotency rejects identity reuse with changed
  content; the application role cannot update or delete the history.

## Verification

Verified locally on 2026-10-17 with synthetic data:

- A real EP-09.03 isolated worker returned a valid source-query proposal, which mediation
  accepted only with matching source, input and output hashes.
- An action-like `submit_application` proposal was rejected as unauthorized.
- Migration graph/offline SQL reached `0025_generated_tool_records`; the development
  database was migrated to that head.
- A rollback-only real `acoa_app` probe idempotently round-tripped request, execution and
  proposal records and confirmed direct delete denial. No synthetic rows remained.
- The final repository gate covers the existing test suite, Ruff formatting/linting,
  strict mypy, dependency consistency, approved-document preservation and the active
  checksum manifest. No test, fixture, mock or testing utility was added or modified.

## Remaining boundaries

Proposals are untrusted planning input and never authorization. Generated tools cannot
send mail, submit forms, create accounts, change the repository or invoke an external
provider. Any later external effect still requires the deterministic Policy/Budget Gate,
an authorized External Action Executor request and the existing execution protocol.
