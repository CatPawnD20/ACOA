# EP-07.01 — Read-only central dashboard

## Scope and requirement links

This task implements the first dashboard slice for `F-12.03`, `F-12.06`, `E-08.04`,
`E-08.06`, `E-11.03`, `P-22` and `ADR-010`. It provides bounded read views only.
Permission changes, task controls, authentication, CSRF, polling and daily-report display
remain in EP-07.02/03.

## Delivered behavior

- Framework-independent immutable view models represent applications, companies, tasks,
  user-waiting items, cost totals and operational performance.
- `DashboardRepository` reads only explicit scalar columns through parameterized queries.
  It never returns stored JSON payloads, message content, evidence, credentials, policy
  bodies or model traces. Search is limited to company labels and application identifiers.
- `PostgresDashboardLoader` owns one short read-only, repeatable-read transaction per
  snapshot and accepts only the authenticated `acoa_app` role under the existing database
  boundary.
- A thin FastAPI factory exposes server-rendered HTML at `/` and the same privacy-limited
  projection as JSON at `/api/dashboard`. Jinja escaping remains enabled, static assets
  ship inside the Python package, and imports open no database or network connection.
- The application factory requires explicit loader injection. No database URL or secret
  discovery, remote listener, login bypass, control endpoint or external action was added.

## Verification

Verified locally on 2026-10-16:

- A transient FastAPI probe rendered both HTML and JSON, normalized a bounded search, and
  confirmed that an HTML-shaped company label was escaped rather than executed.
- A transient container probe used the `acoa_app` role on the internal-only PostgreSQL
  network, loaded real synthetic rows and exercised application-ID filtering. No host
  database port was opened. Both probes were removed afterward.
- The final gate covers the existing test suite, Ruff lint/formatting, strict mypy,
  dependency consistency, wheel package-data inspection, approved-document preservation
  and the active checksum manifest. No test, fixture, mock or testing utility was changed.

## Remaining boundaries

EP-07.02 must add authenticated server-side permission and task controls with CSRF
protection before remote access or state changes are available. EP-07.03 owns polling,
audit masking and daily-report presentation. A dashboard row reports PostgreSQL state; it
does not prove an external provider accepted an action unless the recorded state says so.
