# EP-06.02 — Restart-safe inbox cursor and event reconciliation

## Scope and requirement links

This task implements bounded mailbox polling, provider-event deduplication and
interruption-safe cursor reconciliation for `F-09`, `E-04.02`, `E-04.05`, `E-08`,
`P-12`, `ADR-009` and `ADR-014`. It remains offline: no account, OAuth token, mailbox
or message body was accessed and no notification or message was sent.

## Delivered behavior

- The provider-neutral contract exposes cursor-based change pages independently from
  inbox listing and draft creation. Changes contain only provider event, message and
  thread identifiers; e-mail bodies are not persisted by this slice.
- Gmail history polling maps to `GET /gmail/v1/users/me/history`, requests only
  `messageAdded` changes under the `INBOX` label and uses bounded pages. A provider
  HTTP 404 becomes an explicit `full_sync_required` outcome instead of silently
  resetting an expired history cursor.
- The polling orchestrator retrieves all bounded pages before persistence, rejects page
  token loops and conflicting duplicate event identities, and records the need for an
  initial or recovery full sync without making a provider request from an absent cursor.
- PostgreSQL stores one revision-fenced cursor per opaque account ID, immutable sync
  outcomes and immutable provider events. Event insertion, sync audit and cursor
  advancement share the caller-owned transaction. A crash before commit leaves the old
  cursor; replay then conflicts on the same provider event key instead of creating a
  second local event.
- The fake provider models pagination, current cursors and expired cursors entirely
  offline. No continuous worker, scheduler, push subscription or LLM call was added.

## Verification

Verified locally on 2026-10-16 with synthetic opaque IDs and no real mailbox:

- A transient runtime probe exercised multi-page fake-provider polling, duplicate replay
  suppression, absent/expired cursor handoff, Gmail history mapping and page-token loop
  rejection. The probe was removed afterward.
- Migrations `0016_mailbox_sync` and `0017_mailbox_sync_grants` were applied to the
  dedicated local PostgreSQL service.
  A transaction probe verified checkpoint initialization, event insertion, cursor
  advancement, duplicate replay suppression, immutable event/run grants and rollback
  recovery. The database was returned to the current migration head afterward.
- The final gate passed the existing test suite, Ruff lint/formatting, strict mypy,
  package consistency, approved-document preservation, local links and the active
  checksum manifest. No test, fixture, mock or testing utility was added or modified.

## Remaining boundaries

Full mailbox synchronization still requires a later trusted transport flow to fetch
bounded message metadata and initialize the first verified cursor. EP-06.03 owns reply
and follow-up draft policy; EP-06.04 owns controlled test-mailbox sending and delivery
reconciliation. Live OAuth, message content retrieval and scheduling remain disabled.
